# Problem 3 — example.md не выполняет обязательные требования §8 (пример `sum`, форматы ошибок, manual validation), а `mta docs` не включает object methods и errors/flags

**Задача:** `other/tasks/Task_8.md` — Документация аргументов, signature metadata и команда mta docs
**Вердикт:** Проект не соответствует задаче (статическая проверка, 2026-09-02)
**Серьёзность:** P1 — значимые обязательные требования задачи не реализованы (сквозной пример и разделы §8 в `other/documents/example.md`, покрытие object methods и errors/flags в генерируемой документации), при этом нарушений критических требований безопасности или корректности нет.

## Суть проблемы
Инфраструктура signature metadata и команда `mta docs` реализованы добротно: Spec/Signature хранят name, description, arguments, returns, variadic, category и flags, сигнатуры автоматически выводятся из C++ lambda, недеривируемые случаи явно помечены, а metadata доступна через module_signature/module_functions (API inspection), docgen (`mta docs`) и диагностику ошибок. Однако обязательная документация `other/documents/example.md` не выполняет §8: в ней нет примера `MTA_FUNCTION("sum", ...)`, Lua-вызовов `sum(10, 20)`/`sum(10)`/`sum("10", 20)`, результатов `argument #2 is missing`/`argument #1 has invalid type` (проект использует собственный формат plan §7), объяснения manual validation и явного описания случаев недостаточности automatic binding. Кроме того, `mta docs` покрывает только модульные функции: object APIs (методы MTA_OBJECT/MTA_METHOD) и доступные в metadata flags в сгенерированную документацию не попадают.

### Несоответствие 5 — flags/errors в генерируемой документации — устранено (рек. 6)
- Flags теперь заполняются: `Signature` наследует capability-флаги (`mta::lua::function_flag_variadic`, `function_flag_callback` — выводятся из C++ сигнатуры в `fill_argument_info`), мост регистрации копирует их в `Spec::flags` (`registry.cpp`); docgen выводит декодированные имена флагов («variadic», «callback», «none»).
- Category: ничего не выводимо при регистрации → docgen печатает явный маркер `category: n/a (no registration spelling provides it yet)` (§10); для методов объектов category = имя типа объекта (выводимо).
- Errors: per-function список ошибок не выводим из C++ сигнатуры → docgen печатает явный маркер `errors: n/a (raised errors are not part of the signature metadata; the binder converts them to Lua errors, plan §19)`, что соответствует §10 («если доступны» + явное отражение невыводимого).
- Оговорка: `module_signature` (source/functions/info/functions_list.cpp — замороженная зона для этой волны) по-прежнему не отдаёт flags; чтение Spec::flags из Lua перечислено как экспорт для следующей волны (facade/функции).
