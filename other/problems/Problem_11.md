# Problem 11 — Integration-тесты в CI фактически никогда не выполняются из-за некорректных вызовов CLI

**Задача:** `other/tasks/Task_22.md` — Task 22 — CI: обязательные шаги (build, unit, lua, integration, doctor) и матрица окружений
**Вердикт:** Проект не соответствует задаче (статическая проверка, 2026-09-02)
**Серьёзность:** P1 — значимое нереализованное требование задачи: один из обязательных шагов CI (integration) фактически никогда не выполняется, при этом инфраструктура для него существует и сбой замаскирован `continue-on-error`.

## Суть проблемы
CI-конфигурация (`.github/workflows/ci.yml`) существует и выполняет build, unit, lua и doctor, а матрица покрывает Windows MSVC, Windows MinGW, Linux GCC и дополнительно Linux Clang. Единственное несоответствие — integration: job «integration» подключён к harness, но оба его вызова CLI некорректны (`build win-mingw` без позиционного пресета в cli.py:614-616 и `server test`, отсутствующий в choices cli.py:636), поэтому integration-тесты фактически никогда не запускаются, а `continue-on-error: true` скрывает эти сбои. Исправление вызовов (например, `build --preset win-mingw` и `test integration`) сделало бы задачу полностью соответствующей.

## Рекомендации по устранению
1. В `.github/workflows/ci.yml` (строка 156) заменить `python other/tools/mta/cli.py build win-mingw` на `python other/tools/mta/cli.py build --preset win-mingw`: у подкоманды `build` нет позиционного аргумента пресета (cli.py:614-616), только опция `--preset`.
2. В `.github/workflows/ci.yml` (строка 160) заменить `python other/tools/mta/cli.py server test` на рабочий вызов — `python other/tools/mta/cli.py test integration` либо прямой вызов `python other/server/mta_server.py test` (harness поддерживает подкоманду «test» — mta_server.py:708): «test» отсутствует в choices подкоманды `server` (cli.py:636).
3. Убрать `continue-on-error: true` (ci.yml, строка 140) из job «integration», чтобы сбои integration-шагов не маскировались и приводили к падению CI.
4. После исправления проверить оба вызова локально (argparse больше не должен завершаться с кодом выхода 2) и убедиться, что job «integration» действительно прогоняет integration-тесты через harness other/server/mta_server.py с сервером mtasa-24140 в other/server/.
