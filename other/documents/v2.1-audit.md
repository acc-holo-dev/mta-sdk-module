## 2. Build entry points

- `CMakeLists.txt` — reads `config/module.toml` before `project()`; module
  identity ([module] name/title/author/version) and `[async]`/`[features]`
  flow in as compile definitions; `project(VERSION)` follows `SDK_VERSION`
  in `source/sdk/version.hpp` (regex-parsed, single source).
- `cmake/` (9 files) — module-config reader, platform/baseline options,
  file discovery (`file.cmake`, GLOB_RECURSE + CONFIGURE_DEPENDS), Lua
  static library, per-compiler config, install/packaging.
- `CMakePresets.json` — `base` (hidden) + `win-msvc`, `win-mingw`,
  `linux-gcc`; build/test presets per platform; Ninja; Release.
- Targets: `sdk_core` (object), `sdk_base` (`${SDK_MODULE_NAME}.dll/.so`,
  6-symbol export via generated .def / version script), `sdk_tests`,
  `sdk_docgen`.

## 3. Test entry points

- `sdk_tests` — embedded Lua 5.1 harness (mock manager, unbuffered
  progress output, per-assertion lines), runs all scripts in
  `other/tests/lua/scripts` plus C++ async regressions in `main()`.
- `other/tests/unit/` — CMake-script TOML config tests

- `mta doctor` — environment/project readiness probe.
- 2 CTest entries wire all of the above (`ctest --preset <p>`).

## 5. Version flow (single sources)

- `source/sdk/version.hpp`: `SDK_VERSION "1.0.0"`, `SDK_ABI_VERSION "1"`
  → parsed by `project(VERSION)`, exposed via `mta::sdk_info()`, printed
  by doctor as distinct checks.
- `config/module.toml` `[module] version = "2.0.0"` → float "2.0" →
  `SDK_MODULE_VERSION` define → InitModule/module_details/sample_version.
- MTA server version: runtime-only (load diagnostic).
- v2.1 action: bump module.toml to `2.1.0`; tag `v2.1.0`; SDK/ABI values
  stay (separate concepts, §19 of the release plan).

## 7. Findings — release blockers (must fix before v2.1.0)

1. `cmake/` still at the root (9 files) — target is `config/cmake/`
   (release plan §3/TASK 02/TASK 20). All `include(cmake/...)` references
   in CMakeLists.txt must be updated together; presets/CLI/CI/docs must be
   re-checked for path references.
2. Agent/planning artifacts still tracked: `HANDOVER.md`, `PROMT.md`
   (root), `other/tasks/` (25), `other/problems/` (13),
   `other/documents/v2-audit.md`, `other/documents/v2-phase-reports.md`
   (TASK 04/TASK 13: delete).
3. Development-process references in public content: ~250 lines mention
   `plan §N` / `PHASE N` / `Task N` / `Problem N` across source comments,
   docs, test scripts, harness, CLI, CHANGELOG, CONTRIBUTING, module.toml
   header, workflows. All must be rewritten as standalone technical
   statements (§17/§27); technical rationale stays, process pointers go.
4. `CHANGELOG.md` mixes process language into user-facing entries; needs a
   clean `[2.1.0]` section set (§17).
5. `mta doctor` prints `[ok]`/`[warn]` only — needs PASS/WARN/FAIL/SKIPPED
   differentiation and fix hints (TASK 10).
6. `README.md`/docs contain `plan §` pointers and must be re-audited after
   every code change (TASK 13/14/23).
